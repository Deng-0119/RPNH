## Integrated boundary

OpenCode is an optional presentation client. The authenticated loopback
HTTP/SSE projection delegates provider execution, MainSession state,
independent child Registries, checkpoints, terminal results, workspace/tool
authority, and Petri-net inspection to existing RPNH components. It does not
introduce another provider, permission, recovery, or Registry stack.

The client receives a public catalog of user-configured RPNH profiles without
credentials, private endpoints, or configuration paths. Model changes are
allowed only between main turns, and each turn retains its selected profile
evidence. Frontend exit checkpoint-stops active main turns before releasing the
application owner while independent child workers continue. Unknown owner
outcomes remain explicit and are not replayed.

## Remaining declared limitations

- OpenCode 1.18.32 must be installed separately and exactly match the pin.
- Permissions and attachments are unavailable; unsupported effect routes fail
  closed. Stock OpenCode may still display native commands it owns.
- UI usage/cost/context numbers are unknown display sentinels, not accounting.
- Petri-net commands return the existing RPNH projection as command output;
  the shared browser dashboard remains available through `rpnh net --view`.
- This is offline integration evidence, not a real provider experiment and not
  a claim that a new remote repository has already been published.
