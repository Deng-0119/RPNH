# Next smallest execution-material contract (proposal, not implemented)

The next step should make the existing HOST boundary enumerate its public inputs explicitly. It should not infer completeness by introspecting arbitrary Python callables, walking user configuration directories or adding another execution authority.

1. Extend the original selected-installed HostProfile/Registration composition with an explicit finite material contract. The selected installed entry owns the implementation identity, registered declaration keys, supported payload kinds, public logical material names, immutable bytes/digests, and dependencies it requires. No request-provided import path, pickle, callable or executable locator is accepted. Profiles lacking that contract remain unsupported before invoking preparation factories.
2. Publish the public material contract and each public configuration body through the existing RegistryRegistrationGateway/private-system publication path, with the actual bootstrap/task/source lineage and exact ResourceVersionRefs. Reuse `declaration_refs` and `schema_refs`; add a narrowly typed material producer/schema in the original Registry rather than a side ledger. References in schema/payload business data remain inert; only designated contract reference fields undergo exact-ref resolution.
3. An opaque secret-binding identity names the preexisting HOST credential route and permitted service/account binding. It carries no value, private path, environment contents, secret hash, headers or credential bytes. Resolve the value only through the existing secure HOST channel at execution time. Credential rotation does not by itself rewrite the public inventory; changing account/route/policy identity does. Missing credentials can veto execution, never authorize a different account or broaden permissions.
4. The installed contract must enumerate all public material affecting its lowerer, executor, tool, schema/catalog, plugin, service, HOST binding/configuration and model/route/runtime policy. Public artifacts must be frozen as bytes; an arbitrary mutable filename is not material. The original factory is permitted only if its supported preparation contract is declaration-only. A broad callback without a registered dependency closure is explicitly unsupported, not an empty/default profile.
5. For AgentTask, use the existing Spec serializer at the final derived document_root and the existing builder/Registration APIs, but replace private-file policy projection with a dedicated public/opaque-binding projection supplied by that installed contract. The helper must never read secret-bearing files merely to redact them. The two payload tags should then consume the same typed material inventory, rather than flattening Module into AgentTaskSpec.
6. Keep K -> T/task-id/document_root -> normalized public D -> Registry intent I -> envelope E acyclic. Exact target paths are determined before D; protected runtime origin refs are produced after child bootstrap and are never backfilled into D. Rechecks at original pre-dispatch and worker gate compare the same frozen public bytes and registered installation identity. Drift is fail-closed, with no second policy matcher.
7. Only after the original Registry validates the new complete contract may it yield complete PreparedChildMaterials. The declaration-only type in this candidate must not be reclassified through a Boolean, profile name, unchecked label or digest substitution. Original PN resources and claims remain the sole positive execution permission.

Needed offline tests before that increment can claim completeness: real registered public material/source/declaration refs; undeclared public dependency rejection; public material mutation; unchanged-path/changed-bytes conflict; opaque secret rotation without value reads; changed binding/account rejection; schema/ref-shaped business-data non-resolution; both payload normalization paths; missing or ambiguous installed entries; and no socket, URL, subprocess, private file or credential access during preparation. Native receipt/reservation/worker tests remain a separate later gate.
