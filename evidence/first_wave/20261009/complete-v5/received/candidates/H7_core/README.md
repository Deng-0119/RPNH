# H7 Registry core offline candidate

This is an isolated candidate over the pinned, independently accepted S1 source. It is not merged or published. It does not enable production parent-bound task execution.

## Implemented slice

- Exact canonical request/material/target preparation and Registry-owned intent, dispatch, worker-observation and acceptance records.
- Parent records remain in the original producer's PROVISIONAL firing scope, with the original native Start, claims, run authority, writer fence and single whole-run slot checked in the same transaction.
- The first/replay EventStore boundary rechecks H7 before its normal exact-transaction early return.
- Native child bootstrap/genesis can stage one protected marker through a private, sealed native-evidence boundary. One protected origin/capability transaction supplies an exact native resource to the original Module net/M0 and S1 static reference semantics.
- Initial bound net/admission/Start/I/O/Success conservation checks; bound writable reentry and successor adoption are rejected without changing ordinary Modules.
- A narrow protected-catalog bridge retains the original catalog source and exact root/schema material instead of disguising the capability as an application resource.

## Not an executable native feature

No normal constructor issues native evidence. The tests deliberately use object.__new__ in tests/parent_child_fixtures.py to stand in for observations that must eventually come from the original OS transport boundary. The Registry facts, SQLite transactions, compiler, admission, Start, products and child Success are real; kernel peer authentication, complete receipt delivery and physical target reservation are not tested or provided.

There is no production parent gate, Popen/dispatch ticket issuer, native receipt parser, AgentTask/Module bound-create adapter, physical target reservation, full installed material collector, or parent observation/completion adapter. Parent native-launch Success is explicitly UNSUPPORTED until observation/completion is connected, retaining its claim rather than producing a false terminal result. No public start_run/run_agent_task interface accepts a caller receipt or permission Boolean.

The test bound Core is created in a disposable offline fixture before evidence injection. This proves neither production Core-before-reservation ordering nor existing-target zero-touch. Physical reservation remains a separate required slice; no directory is treated as business authorization.

The historical acceptance reader/classifier, real two-way peer checks, owner-loop sticky-stop ordering, general mechanical lowering for both payload kinds, and complete material assembly remain unimplemented. H7 overall D0, D1, H7b and consumer migration are not declared complete.

See IMPLEMENTATION_SLICE.md, VALIDATION.md, SOURCE_IDENTITY.json and NATIVE_HANDOFF.md for exact evidence and remaining boundaries.
